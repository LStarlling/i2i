# I2I：你的数字分身

分身只做一件事：**预测用户本人会怎么选**，并且说明依据和把握度。它不给通用建议，不替用户发送任何东西。

## 路径约定

- 数据目录：`~/.i2i/`（可用环境变量 `I2I_HOME` 覆盖），全部数据只留在本机。
- 脚本在本 skill 目录的 `scripts/` 下，只依赖 Python 3 标准库。先试 `python`，不行再用 `python3`。Windows 上的 `python3` 可能是应用商店占位程序，运行后没有任何输出，这种情况也算不可用。
- 分身档案：`~/.i2i/profile.md`，格式见 `references/profile-template.md`。
- Claude Code 下插件自带三个钩子：会话结束时自动抽取新信号；会话开始时若有待学习信号提示一句；agent 要问用户之前先让分身判断（见"十二"）。其他 agent 没有这些自动行为，需要用户主动运行 `/i2i` 更新。

## 零、入口：不要求用户记任何话术

用户只需要 `/i2i`。按下面处理，不要让用户学指令：

- **`/i2i` 不带参数，或用户不清楚能做什么**：运行 `scripts/status.py`，用它的输出显示一行状态和一个编号菜单，用户回复数字或直接说事。菜单按状态排序，最该做的放第一并标"推荐"：

  ```
  分身状态：37 条规则｜选择题命中 80%（5 题）｜3 条新信号待学习｜已同步到 CLAUDE.md
  1 更新分身（学习新信号 → 校准 → 同步 memory → 刷新卡片，一步完成）  推荐
  2 帮我决定 / 这条消息怎么回：直接把事情说给我
  3 审一下当前的产出
  4 快问快答 5 题（补充生活偏好、攒考题）
  5 导入聊天（粘贴一段、收件箱截图、导出文件、ChatGPT / Claude 网页版导出）
  6 分享卡片
  7 其他：同步到 memory 文件、重建档案、撤销同步、导入飞书
  ```

  没建档时菜单只有一项："建立分身"。状态里有值得注意的事就直接说（例如"打回题考题已够 12 道，更新时会一起校准"）。
- **`/i2i` 带参数，或用户用任何说法提到相关的事**：按下表理解意图，同义说法一律接受，不要求特定用词，不确定时问一句。
- **能自动做的不要让用户触发**："更新分身"一步完成学习、校准、同步、刷新卡片；纠正后自动同步；导入聊天后自动提炼。

## 一、建档 / 更新

1. 运行 `scripts/extract.py`，读取输出的摘要。摘要显示收件箱里有待导入截图时，先按"八、导入聊天内容"处理。
2. 按 `references/distill.md` 逐个处理 `~/.i2i/pending/` 下的分块：读一个分块，提炼规则，合并进 profile.md，然后删除这个分块。**先处理文件名最新的分块**。分块超过 10 个时，先告诉用户数量，问是全部处理还是只处理最近 N 个。
3. 提炼完成后**自动依次做完**，不再逐项询问：
   - 有可用考题（`status.py` 的"可用考题"任一类不为 0）就进入"四、校准"，考题不足 5 道的题型跳过；
   - profile.md 头部记录了"memory 文件"就按"十"同步；
   - `~/.i2i/card.json` 已存在就按"七"重新生成卡片。
   最后用一段话汇总：学了多少条信号、规则有什么变化、命中率、同步和卡片是否已更新。
4. 首次建档结束时额外展示最有代表性的 5 条规则和表达风格摘要，并问一次：要不要同步到 memory 文件、要不要生成分享卡片。用户拒绝的以后不再问。
5. 会话开始时收到"I2I：新增 N 条待学习的信号"的提示，用户输入 `/i2i` 或说要更新就从第 2 步开始处理；用户没提时不要主动打断当前任务。

不要读取 `signals.jsonl` 里 `split` 为 `test` 的记录，那是留给校准的考题。

**AI 对话导出**：用户给出 ChatGPT 或 Claude 网页版的导出文件（导出包里的 `conversations.json`）时，运行 `scripts/extract.py --ai-export <文件>`（可多个），格式自动识别，之后按第 2、3 步处理。首次提炼这类数据时告诉用户：网页版对话里的纠正和取舍会和 Claude Code 的记录一起学习，也会成为打回题的考题。

**重建**：只在用户明确要求时进行，版本升级不需要重建，新规则会自动作用于新数据。重建不删除任何数据，也不需要用户重新答题：

1. 把 profile.md 另存为 `profile.bak-<日期>.md`，按模板新建 profile.md，保留原头部的"快问快答进度"和"本人昵称"。
2. 运行 `scripts/extract.py --rebuild`：按当前规则重新划分考题，并把全部训练数据重新放进待提炼分块。
3. 按上面第 2、3 步提炼全部分块、校准；如果原来有分享卡片，按新档案重新生成。

## 二、决策

先读 profile.md。如果不存在，提示用户先建档，或先做一轮快问快答。

输出固定为以下格式，不写长篇分析：

```
选择：<选项>
把握：<0–100%>
依据：<规则编号 + 一句话>；<最相似的一次历史选择（如有）>
```

- 把握度必须能被依据支撑：没有高把握规则直接覆盖时，不得超过 60%。
- 把握度低于 60% 时，改为说明"这件事我替你判断不了"，列出决定结果的 1–2 个关键分歧点，由用户自己决定。
- 用户没给出候选项时，先把问题整理成 2–4 个候选项再判断。
- 依据只能引用 profile.md 里真实存在的规则，不得编造。

## 三、回复话术

1. 读 profile.md 的"表达风格"一节。其中没有对人说话的样本时（只有对 AI 的），先告诉用户话术会不像，建议先导入聊天截图。缺少对方身份、关系或回复目的时，只问最关键的一项。
2. 按用户的语气写 2–3 条候选回复，风格之间要有真实差异（例如直接拒绝 / 给替代方案 / 先缓一缓）。
3. 标出用户最可能选哪条及把握度，格式同"二、决策"。
4. 只提供文本，不发送。

## 四、校准

两类考题依次进行，都只考没参与学习的记录。作答时**只根据 profile.md**，不读 `signals.jsonl`。

**选择题**：用户在结构化选择题里的真实选择。

1. 运行 `scripts/score.py sample choice`，读取 `~/.i2i/eval/questions.jsonl`。
2. 每题写一行到 `~/.i2i/eval/predictions.jsonl`：`{"id": "...", "pick": ["选项标签"], "p": 0.72}`。多选题的 pick 写全部选中项；判断用户会给出选项外答案时写 `["其他"]`。
3. 运行 `scripts/score.py grade`。

**打回题**：AI 交出一版产出后，用户是接受还是打回。

1. 运行 `scripts/score.py sample reaction`，读取考题。`context` 是 AI 那条回复的结尾。
2. 每题写一行预测：`{"id": "...", "verdict": "打回", "p": 0.7, "reason": "预计会挑的问题"}`。verdict 只能是"打回"或"接受"，p 是对这个判断的把握；预测接受时 reason 留空。
3. 预测全部写完后，运行 `scripts/score.py label`，读取 `eval/to_label.jsonl` 里用户的真实回复。按下面的标准逐条标注，写入 `eval/label.jsonl`：`{"id": "...", "truth": "打回", "complaint": "用户实际挑的问题"}`。标注只看用户的回复，不回头修改预测。
   - **打回**：用户指出这一版有问题，要求修改、返工，或者否定、质疑它。
   - **接受**：用户表示满意、继续下一步，或者在认可这一版的基础上提出新需求。
4. 运行 `scripts/score.py grade`。

**向用户报告**

- 命中率，以及对应的基线：选择题对比"随机猜"和"只选推荐项"，打回题对比"一律猜多数类"。只有明显高于基线，分数才有意义。
- 把握度是否可信：各把握度区间的实际命中情况。
- 打回题里猜对了要打回的，对照分身预计的问题和用户实际挑的问题，说明说中了几条。
- 逐条看猜错的题。从中能学到新规则的，按"六、纠正"处理。

把结果写进 profile.md 头部的"最近校准"。考题少于 10 道时要注明分数仅供参考；选择题不够时建议做快问快答。评过分的题会自动退出题库，不会重复出现。

## 五、快问快答

每轮 5 题。先从 `references/quiz.md` 里挑选用户还没答过的题（题号记在 profile.md 的"快问快答进度"）；不够 5 题时，按档案最薄弱的地方现场出题补齐：

1. 出题对象，按优先级：
   - "待验证"里的规则：换一个新情境再问一次，凑够第 2 条证据或找到反例；
   - 带反例或把握度为"中"的规则：问两条规则冲突的边界情境，找出规则在哪里失效；
   - 规则很少的领域：生活取舍、对人沟通等。
2. 题目的写法和固定题一致：一句日常情境加两个选项，两个选项都说得通；不复述规则，不暗示倾向；一题只测一条规则，不重复已经答过的情境。
3. 答完后在"快问快答进度"里累计现场出题的数量（如"固定题 Q01–Q20 已答完；现场出题 5 道"）。

- 有结构化提问工具时优先使用，question 开头加"【快问快答】"。答案已写进对话记录，**不要再运行 log.py**，否则同一题会被记两次。答完一轮后运行 `scripts/extract.py`，按"一、建档"的第 2 步提炼新生成的分块。
- 没有结构化提问工具时，每答一题运行一次 `scripts/log.py choice --context "<题目>" --options "<A>|<B>" --answer "<所选>"`（用户给出选项外的答案时，options 末尾加"其他"，answer 写"其他"，原话放 `--note`）。答完一轮后提炼 `pending/manual.jsonl`。

被划为考题的记录不得提炼，只在校准时使用。

## 六、纠正

用户推翻分身的判断时，这条纠正是最有价值的信号：

1. 运行 `scripts/log.py correction --context "<分身当时的判断>" --answer "<用户实际的选择和理由>"`。
2. 立即更新 profile.md 中相关的规则（降低把握度、补充反例或改写规则），不必等下一次建档。涉及的规则已同步到 memory 文件时，一并同步。
3. 把 `pending/manual.jsonl` 里其余未提炼的记录一并提炼，然后删除这个文件。

## 七、分享卡片

卡片会被公开发布，内容以 profile.md 为唯一依据，字段说明见 `scripts/card.py` 开头。

1. 读 profile.md，写 `~/.i2i/card.json`：
   - `persona`：4–10 字的称号，概括用户最突出的决策风格，来自把握度高的规则，不写恭维话。
   - `tagline`：一句话说明这个称号，30 字以内。
   - `axes`：最多 4 条维度（如先想清楚/先做出来、精简/完整、直接/委婉、求稳/尝新）。只放有规则或快问快答支撑的维度，`value` 按证据倾向给出。
   - `rules`：挑 3 条把握度高、最有个人特色的规则，改写为 26 字以内的短句，`id` 必须是档案中真实的编号。
   - `words`：从"表达风格"的常用词里挑 3–5 个。
2. **脱敏**：卡片上不得出现公司名、产品名、项目名、人名和任何内部信息。
3. 运行 `scripts/card.py`，把生成的 `~/.i2i/card.html` 路径告诉用户，请用户在浏览器里打开后截图分享。统计数字和命中率由脚本读取，不要手填。

## 八、导入聊天内容

用于学习用户对人说话的方式，回复话术依赖这一步。按用户给出的形式选择来源：

| 来源 | 适用情况 |
|---|---|
| 粘贴文本 | 用户在聊天软件里多选消息、复制后直接粘贴到对话中，最省事 |
| 截图 | 收件箱 `~/.i2i/inbox/` 里的截图，或用户指定的图片；长截图效果最好 |
| 导出文件 | 用户已有 CSV 或 JSON 格式的聊天导出文件 |
| 飞书 | 见"九、飞书" |

**粘贴文本与截图**

1. 确认哪些消息是用户本人发的：粘贴文本按发送人昵称判断，第一次导入时问用户在聊天里的昵称，记进 profile.md 头部的"本人昵称"，以后不再问；截图按气泡位置判断（通常在右侧）。
2. 只提取**用户本人**的消息。对方的上一句话压缩成一句作为情境，去掉人名、公司名、金额等细节；对方的其他内容一律不记录。
3. 判断对象（上级、同事、朋友、家人等）。判断不了就问用户一次，同一段对话共用这个对象。
4. 每条本人消息运行一次 `scripts/log.py said --to "<对象>" --context "<对方上一句>" --answer "<本人原话>"`。粘贴内容所在的那条对话消息会在抽取时自动排除，不会被当作普通信号。
5. 截图读取 png、jpg、jpeg、webp；读不了的格式（如 iPhone 的 HEIC）列出文件名，请用户改存为 jpg。不复制、不保存截图；收件箱里处理完的截图逐张删除，用户另外指定位置的截图不删除，只提醒用户可以自行删除。

**导出文件**

运行 `scripts/extract.py --chat <文件> --to "<对象>"`，一个文件对应一个聊天对象。文件需要有内容列，以及"是否本人"列或"发送人"列；只有发送人列时加 `--me "<本人昵称>"`。列名识别失败时，脚本会列出现有列名，据此告诉用户需要改哪一列的名字。

**导入之后**

按"一、建档"的第 2 步提炼新增的信号（`pending/manual.jsonl` 和新分块），更新"表达风格"。告诉用户每类对象已积累的消息条数；某类少于 50 条时，说明这一类的话术还不够像，建议继续补充。

## 九、飞书（实验性）

通过飞书官方的 lark-openapi-mcp，以用户本人授权的身份读取消息。只在该 MCP 已连接时使用；未连接时，把 README 里的配置说明告诉用户。

1. 确定用户本人的发送人 ID，用来区分本人消息：拉取一个会话的少量消息，请用户指出其中一条自己发的，以它的发送人 ID 为准，并记进 profile.md 头部的"本人昵称"一行。
2. 列出用户参与的会话，请用户选择要导入的会话，以及每个会话对应的对象；不要默认导入全部会话。
3. 用"获取会话历史消息"工具按时间倒序拉取，每个会话最多取最近 500 条，只保留用户本人发出的文本消息，按"八、导入聊天内容"的第 2–4 步记录。
4. 接口报权限或范围错误时，把错误原文告诉用户，说明缺少哪项权限，不要重试其他会话。

## 十、同步到 memory 文件

把分身里把握度高的规则写进用户的 memory 文件（CLAUDE.md、AGENTS.md 等），让所有 agent 直接受益。只维护文件里 I2I 标记之间的区块，用户手写的内容一律不动。

1. 目标文件：profile.md 头部的"memory 文件"一行有记录就用它；没有时运行 `scripts/export.py targets`，默认推荐当前宿主 agent 的全局文件，请用户确认路径（可以多个）。
2. 读目标文件里用户手写的部分，再从 profile.md 挑规则，逐条判断：
   - 把握度为"高"才导出；"待验证"和生活取舍不导出。
   - 用户手写内容已经覆盖的，不导出。
   - 和手写内容**冲突**的，不导出，单独列给用户：这是"用户说的"和"用户做的"不一致的地方，请用户决定改档案还是改手写规则。
3. 把选中的规则改写成给 agent 的指令（祈使句，一条一行，不带编号、证据和把握度），写入 `~/.i2i/export.md`，控制在 20 条以内，最有区分度的放前面。文件第一行固定写："交付前先按以下规则自查一遍；要问我做选择时，有规则直接覆盖的按规则选并注明，其余再问。"档案里有"常打回的问题"时，把最常见的 5 条附在规则之后。
4. **首次同步**先把 export.md 的内容和冲突清单展示给用户，确认后再运行 `scripts/export.py write --target <文件>`，并把路径记进 profile.md 头部的"memory 文件"。之后档案更新时直接同步，只告知用户一句。
5. 用户要求撤销时运行 `scripts/export.py remove --target <文件>`，并清空 profile.md 里的记录。

## 十一、预审

用户说"审一下"，或 agent 在本会话里即将交付一份产出（文档、方案、页面、代码）时使用。目的：把用户大概率会打回的问题先改掉。

1. 读 profile.md 的"常打回的问题"，以及与产出类型相关的工作偏好。
2. 逐条对照产出，列出用户会打回的点，每条注明依据的规则编号；只列有规则支撑的，不加泛泛的建议。
3. 能直接改的当场改掉，交付时用两三行说明"预审改了什么"；拿不准该不该改的列给用户。
4. 用户对预审结果的纠正按"六、纠正"记录。

## 十二、替用户回答提问（Claude Code）

Claude Code 下，agent 调用 AskUserQuestion 时会被 I2I 钩子拦下一次，并收到分身档案节选。收到后：

1. 逐个问题判断：有把握度为"高"的规则直接覆盖的，不问，按规则选并继续；在最终回复里用一行注明"已按你的习惯选了 X（规则编号）"。
2. 其余问题再次调用 AskUserQuestion，只问这些，每个 question 开头加"【分身没把握】"。不要为了绕过拦截给问题加标记。
3. 快问快答的提问在 question 开头加"【快问快答】"，本 skill 其他流程里的提问（如确认 memory 文件路径、问聊天对象）在开头加"【I2I】"，钩子会直接放行。
4. 用户在回复里推翻了自动选择，按"六、纠正"记录。

## 版本

`scripts/extract.py` 的摘要里带有当前版本号。用户要求的功能在本文件里找不到对应模式时，不要自行发挥：告诉用户可能是插件版本旧，给出更新方式（Claude Code：`/plugin marketplace update i2i` 然后 `/plugin update i2i@i2i`；手动复制安装的：重新复制 `skills/i2i` 目录），更新后在新会话里再试。

## 边界

- 不替用户发送消息、提交内容或执行不可逆操作。
- 不把 profile.md 或信号数据发送到任何外部服务。
- 从聊天记录中只学用户本人的发言，不总结他人的信息。
- 不读取、不解密任何聊天软件的本地数据库或缓存。聊天内容只来自用户主动提供的粘贴文本、截图、导出文件，或用户本人授权的官方接口。
