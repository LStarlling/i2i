# 提炼规则

目标：从信号中提炼出**能直接用来做判断**的规则，而不是描述用户"是个什么样的人"。

## 信号字段

- `kind`：`choice` 结构化选择 / `reaction` 对 AI 回复的反应 / `said` 本人发言原文 / `correction` 对分身的纠正
- `context`：当时的情境（问题或 AI 上一条回复的结尾）
- `answer`：用户的选择或原话；`note`：用户在选项之外的补充
- `project`、`ts`：所在项目和时间

## 信号的价值排序

1. `correction`：用户明确推翻了分身的判断。
2. `choice`，尤其是选了"其他"或附带补充说明的：用户在选项之外表达了真实想法。
3. `reaction` 中的否决、改写、追问：例如"不要……""改成……""为什么……"。
4. `reaction` 中的普通任务指令：大多只是在执行任务。只有同类要求**反复出现**时，才提炼成规则。
5. `said`：只用于"表达风格"一节。

## 什么算规则

- 写成可执行的判断："A 与 B 冲突时选 A"，或"遇到 X 时，要求 Y"。不写"注重细节""追求高效"这类形容词。
- 能跨任务复用。"第 12 页流程图放中间"是一次性的任务细节，不提炼；如果多次出现"图居中、文字在右"，才提炼成排版偏好。
- 用户用自己的话讲出来的原则，优先保留原话。

## 合并进 profile.md

- 与已有规则含义相同：追加证据 id，按下面的标准重新评定把握度。
- 与已有规则冲突：以时间更新的信号为准，除非旧规则的证据明显更多。把冲突的信号记为反例；两边证据相当时，把规则挪到"待验证"。
- 新规则只有 1 条证据：放进"待验证"，积累到 2 条后再移入正式分类。
- 把握度：**高** = 至少 3 条独立证据且无反例；**中** = 2 条证据，或有反例但多数一致；**低** = 其余情况。
- 规则编号 `R<n>` 一经分配就不再改动，保证决策时引用的编号一直有效。删除的规则留空号。
- 正式规则控制在 80 条以内。超出时，合并相近规则，或淘汰把握度低且长期没有新证据的规则。

## 表达风格

从 `said`，以及 `reaction` 里用户自己的原话中归纳：

- 句长、语气（直接或委婉）、常用词、标点和分点习惯、中英文混用程度
- 不同对象下的差异：`said` 的 `to` 字段标明了对象（上级、同事、朋友、家人），对 AI 的说话方式单独归纳，不能拿来代表对人的风格；样本不足时不要编造
- 附 2–3 条脱敏后的原话短例
